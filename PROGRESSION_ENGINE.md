# Fixed-load progression — M4 planned

Deterministic, versioned function of exercise-specific rule, comparable completed sessions and prescribed targets. Output: hold/regress/progress recommendation, explanation, proposed prescription and evidence IDs. No automatic significant changes. Missing data yields hold with explanation. Historical edits recompute fitness analytics without issuing new rewards.

Conservative default (developer policy pending program review): require two comparable fully completed sessions at upper rep target, every relevant set RIR ≥2, no pain flag, stable load/tempo and no unexpectedly shortened rest before offering slower eccentric. The brief's 12/12/11/10 example remains rep progression until all sets meet the criterion. Never infer pain absence from an unfilled field when pain was recorded for the session.

Ladder: reps → slower eccentric → longer pause → bounded rest reduction → extra prescribed set → 1½ reps → approved unilateral variation → approved superset → rest-pause → mechanical drop. Advanced techniques are disabled by default and require per-exercise allowlists and maximums. Rest cannot fall below rule minimum; set count cannot exceed prescribed cap. Recovery or deload recommendation takes precedence over escalation when decline is repeated.

Comparison keys include exercise variant, side, load convention, implement count, tempo and prescription revision. Mixed variants/loads, skipped sets and partial sessions cannot satisfy an all-sets threshold. AMRAP/timed work use separate rules. Density PRs never automatically shorten recovery.

Parameterized tests: threshold boundaries, 4+ RIR, nil RIR, unilateral asymmetry, changed load/tempo, partial/edited/duplicate histories, maximum caps, repeated decline, no qualifying history, and deterministic repeatability. Every recommendation stores rule version for auditability.
